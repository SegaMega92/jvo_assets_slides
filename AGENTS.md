## 2. Принципы (из `/frontend-slides`) — НЕ нарушать

1. **Viewport-fit обязателен.** Слайд = ровно один экран 1920×1080, без внутреннего скролла и без обрезки. Контент не помещается → разбей на два слайда, НЕ ужимай шрифт ниже читаемого. (В нашем проекте это гарантирует `SlideStage`, но следи за переполнением внутри.)
2. **Отличительный дизайн.** Никаких дженерик-градиентов и «Inter на белом». Используем фирменную палитру JVO (eggplant `#410031`, pink `#FF8FDA`, lime, тёмные секции) и пары Unbounded/Manrope.
3. **Show, don't tell.** Решения принимаются по скриншотам, а не на словах. Любую сборку проверяй визуально (см. §5).
4. **Осмысленная анимация, не шумная.** Reveal-on-enter, уважение `prefers-reduced-motion`.
5. **Production-quality.** Код с комментами, переиспользуемые компоненты, без дублей.

### Лимиты плотности (держать, если не просят плотнее и читаемость сохраняется)
| Тип слайда | Максимум |
|---|---|
| Титул | 1 заголовок + 1 подзаголовок + опц. таглайн |
| Контент | 1 заголовок + 4–6 пунктов / 2 коротких абзаца |
| Сетка карточек | 6 карточек |
| Цитата | 1 цитата + автор |
| Изображение | 1 картинка в пределах вьюпорта |

### Анти-паттерны
Стены буллетов; дженерик-градиенты без айдентики; системные шрифты; фикс-высоты, которые рвут контент; текст ниже читаемого ради «влезания».

## 3. Архитектура и где что лежит

```
src/v2/
  SlideStage.tsx     # холст 1920×1080: <SlideStage>, <Abs x y w h>, pt(), u(), ASSET_BASE
  assets.ts          # img(deck, file) → URL извлечённой картинки (/v2assets)
  components/kit.tsx  # «позиционируемый» кит для СЛАЙДОВ (Card/JBadge/SlideTitle/Text/Marker/Pill/Check)
  lib/                # БИБЛИОТЕКА автономных компонентов «Слайдкит» (для НОВЫХ презентаций)
    primitives.tsx · cards.tsx · lists.tsx · tables.tsx · brand.tsx + *.stories.tsx
  slides/             # сами слайды-стори: Enterprise / KpDjivio / Studia (.stories.tsx)
```

**Система координат.** `SlideStage` рисует 1920×1080. `<Abs x y w h>` принимает координаты в системе **исходного PPTX 960×540** и сам умножает на 2. `pt(n)` переводит типографские pt в px холста (`1pt = 2.667px`).

**Две «семьи» компонентов — не путать:**
- `src/v2/components/kit.tsx` — **позиционируемые** (принимают `x/y`), используются ВНУТРИ слайдов поверх `SlideStage`.
- `src/v2/lib/*` — **автономные** (БЕЗ `x/y`, только данные + вариант), это переиспользуемая библиотека «Слайдкит» с autodocs. Для новой презентации бери их.

## 4. Как собирать

### Режим A — воспроизвести слайд 1:1 из PPTX
1. Достань спецификацию слайда: `../jvo-presentation-v2/.venv-pptx/bin/python ../jvo-presentation-v2/scripts/dump.py ../jvo-presentation-v2/extracted/<deck>/slideNN.json` — даёт координаты/текст/цвета/радиусы/картинки.
2. Фон-картинка слайда (если есть): хелпер `bg('bg_*.png')`; карта — в `scripts/extract_bg.py`. Сплошной тёмный фон мастера задаётся цветом вручную.
3. Собери стори в `src/v2/slides/<Deck>.stories.tsx`: `SlideStage` + `Abs` + кит. Координаты — в 960×540 (×2 делает `Abs`).
4. **Текст НЕ вкладывай в `Card`** — вложенный `Abs` удвоит смещение. Клади соседним элементом с `z`.
5. Сверь с эталоном `../jvo-presentation-v2/ref/<deck>/slide-NN.png` (см. §5).

### Режим B — новая презентация из «Слайдкит»
1. Уточни у пользователя минимум: цель (питч/обучение/апдейт), объём (S/M/L), состояние контента. Если контент есть — попроси вставить до стилизации.
2. **Подбор стиля — визуально:** собери 2–3 превью-слайда (разные акценты палитры/мотива) и покажи скриншоты, дай выбрать/смешать. Не спрашивай абстрактными анкетами.
3. Композиция слайда: `SlideStage` + раскладка (flex/grid или `Abs`) + компоненты из `src/v2/lib/` (StatCard, IconFeatureCard, ComparisonTable, TariffCard, ArrowList, CheckList, PriceList, Pill, Tag, …). Один doc-пример на компонент — в Storybook «Слайдкит».
4. Соблюдай §2 (плотность, viewport-fit, айдентика).

## 5. Цикл визуального QA (обязателен, как в `/frontend-slides`)

**Считай, что с первого раза неверно. Ищи проблемы, а не подтверждай успех.**

```bash
export PATH="$HOME/.nvm/versions/node/v22.22.0/bin:$PATH"
# 1) Снять скрин стори (id в кебаб-кириллице, напр. презентации-enterprise--слайд07):
node scripts/shoot.mjs "<storyId>" /tmp/our.png
# 2) Склейка с эталоном для сравнения (Python+PIL):
#    our слева | ref справа → cmp/<deck>/cmp-NN.png  (примеры см. в истории проекта)
# 3) Контакт-лист всего дека для обзора: см. qa/sheet_*.png
```

- Сравнивай OUR vs REF (для режима A) или OUR vs макет (режим B). Чини до совпадения.
- На больших объёмах — **поручай сверку субагенту со свежим взглядом** (он читает склейки и выдаёт список расхождений), правки вноси сам.
- Ищи: переполнение/обрезку, наезды элементов, неверные переносы, низкий контраст, несоответствие цветов/радиусов, z-order (декор поверх текста).

### Валидация размеров (перед сдачей)
Проверь, что слайд читаем и не ломается на: **1920×1080, 1280×720, 768×1024, 375×667**. `SlideStage` масштабируется целиком — убедись, что внутри нет переполнения.

## 6. Гочи и правила устойчивости (выстрадано в QA)

- **Длинные слова** → `overflowWrap/wordBreak: break-word` (иначе вылезают за край). Уже встроено в `Surface` и списки библиотеки.
- **Карточки** — `minHeight`, НЕ фикс. `height` (иначе контент вытекает вниз).
- **Pill/Tag** — переносятся (`maxWidth:100%`), не `nowrap` на длинном тексте.
- **Цена в тарифе** — единица под числом; число склеено неразрывным пробелом (` `), чтобы не рвалось.
- **Таблицы** — колонки `minmax(0, 1fr)` + `break-word`, иначе длинный заголовок распирает/обрезается.
- **Скрытые слайды PPTX** (`show=0`) LibreOffice пропускает — для эталонов временно раскрывай (см. пайплайн в памяти).
- **Кириллические story id**: title `Презентации/Enterprise` → `презентации-enterprise--слайдNN`.
- Менял общий компонент (`SlideStage`, кит, lib) — это затрагивает ВСЕ слайды; перепроверь несколько.
