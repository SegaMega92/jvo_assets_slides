# План дизайн-аудита JVO PPTX → Storybook

## Общая цель
Извлечь из реальных PPTX-файлов точные значения цветов, типографики и геометрии слотов.
Все данные — из XML через python-pptx, без угадывания по картинкам.

## Шаги

### Шаг 1 — Скопировать PPTX в проект и проверить читаемость

**Что делаю:**
Копирую 4 приоритетных файла в `jvo_assets_slides/source_pptx/`.
Пишу минимальный Python-скрипт `scripts/check_files.py`, который открывает каждый файл через python-pptx и выводит: число слайдов, есть ли slide master, есть ли тема.

**Чего не делаю:**
Не анализирую содержимое — только проверяю что файлы открываются без ошибок.
Не трогаю архивные файлы (папка `⛔ Архив`).

**Проверка:**
Скрипт завершается без исключений. Для каждого файла в консоли: `OK: N slides, master: yes, theme: yes`.

---

### Шаг 2 — Установить окружение: python-pptx + зависимости

**Что делаю:**
Создаю `scripts/requirements.txt`:
```
python-pptx
colormath   # для конвертации цветовых пространств
Pillow      # только для сохранения цветовых свотчей в PNG-отчёт
```
Устанавливаю через `pip install -r scripts/requirements.txt`.

**Чего не делаю:**
Не ставлю LibreOffice и не рендерю слайды в PNG — весь анализ идёт через XML.
Не использую `colorthief` или любые pixel-based инструменты.

**Проверка:**
`python -c "from pptx import Presentation; print('OK')"` выводит `OK`.

---

### Шаг 3 — Извлечь официальную тему: theme colors

**Что делаю:**
Пишу `scripts/extract_theme.py`. Для каждого файла читаю `ppt/theme/theme1.xml` через `prs.slide_master.theme_color_map` и `prs.slide_master.element`.
Извлекаю 12 слотов темы PowerPoint:
`dk1, lt1, dk2, lt2, accent1–6, hlink, folHlink` — каждый с hex-значением.
Сохраняю в `analysis/theme_colors.json`.

**Чего не делаю:**
Не интерпретирую роли сам на этом шаге — только записываю что есть в теме.
Не смотрю на shapes — только тема.

**Проверка:**
`theme_colors.json` содержит hex для всех 12 слотов по каждому файлу.
Сравниваю dk1/lt1 между файлами — должны совпадать если это одна система.

---

### Шаг 4 — Извлечь все цвета со всех shapes (полный дамп)

**Что делаю:**
Пишу `scripts/extract_colors.py`. Прохожу по каждому слайду, по каждому shape:
- `shape.fill` → solid fill hex, если есть
- `shape.line.color` → цвет обводки
- Для `shape.has_text_frame`: по каждому `run` → `run.font.color.rgb`
- Для `shape.shadow`, `shape.glow` — пропускаю (декоративно)

Каждую запись сохраняю как `{ file, slide_index, shape_name, role: "fill|line|text", hex, theme_slot_if_any }`.
Итог: `analysis/all_colors.json` — плоский список всех цветовых вхождений.

**Чего не делаю:**
Не усредняю и не фильтрую — это сырые данные.
Не трогаю цвета из slide master на этом шаге.

**Проверка:**
Число записей > 500 (достаточно для статистики).
Нет `None` / `null` hex — пропускаем shape'ы без явного цвета, не подставляем дефолт.

---

### Шаг 5 — Частотный анализ: построить цветовую карту

**Что делаю:**
Пишу `scripts/color_frequency.py`. Читаю `all_colors.json`, группирую по hex:
- Считаю частоту (сколько раз встречается)
- Считаю % от общего числа
- Разбиваю по роли: fill / line / text
- Сортирую по убыванию частоты

Дополнительно: для каждого цвета считаю на скольких разных слайдах он появился (spread) — это важнее чем просто частота.

Сохраняю `analysis/color_frequency.json` и текстовый отчёт `analysis/color_report.txt`.

**Чего не делаю:**
Не схлопываю похожие цвета (например #F4336B и #F33368) — это разные записи, схлопывание сделаем вручную при анализе.

**Проверка:**
Топ-3 цвета по spread занимают >60% от числа слайдов — это и есть основная палитра.
Отчёт читается за 2 минуты.

---

### Шаг 6 — Извлечь типографику: шрифты, размеры, веса

**Что делаю:**
Пишу `scripts/extract_typography.py`. Прохожу по каждому `text_frame.paragraphs[].runs[]`:
- `run.font.name` — название шрифта (может быть None = наследуется)
- `run.font.size` → EMU → pt (делю на 12700)
- `run.font.bold`, `run.font.italic`
- `run.font.color.rgb`
- `paragraph.alignment` (LEFT/CENTER/RIGHT)
- `paragraph.space_before`, `paragraph.space_after` (межабзацный)
- `paragraph.line_spacing`

Для None-значений поднимаюсь вверх по иерархии: run → paragraph → text_frame → slide_layout → slide_master.

Сохраняю `analysis/typography_dump.json`.

**Чего не делаю:**
Не выбрасываю записи с None — помечаю как `inherited`, чтобы потом восстановить из master.
Не анализирую кастомные XML-атрибуты вне python-pptx API.

**Проверка:**
Для каждой записи есть хотя бы `size_pt` (разрешённое через иерархию).
В дампе видны минимум 3 разных размера шрифта.

---

### Шаг 7 — Извлечь геометрию слотов: позиции и размеры зон

**Что делаю:**
Пишу `scripts/extract_geometry.py`. Для каждого слайда и каждого shape:
- `shape.left, shape.top, shape.width, shape.height` — из EMU перевожу в px (при 96dpi: делю на 914400 * 96) и в % от размера слайда
- `shape.shape_type` (TEXT_BOX, PICTURE, AUTO_SHAPE, PLACEHOLDER)
- `shape.placeholder_format.type` если shape — placeholder (TITLE, BODY, SUBTITLE, etc.)
- `shape.name` — дизайнер мог дать понятное имя

Дополнительно: для placeholder определяю «слот» (заголовок / тело / картинка / логотип / нижняя полоса).
Сохраняю `analysis/geometry_dump.json`.

**Чего не делаю:**
Не пытаюсь угадать Z-order из XML — только позицию и размер.
Не анализирую трансформации (rotate) на этом шаге.

**Проверка:**
Для каждого слайда сумма высот основных shape не превышает высоту слайда.
Координаты в % выглядят разумно (0–100%).

---

### Шаг 8 — Проанализировать slide master и slide layouts

**Что делаю:**
Пишу `scripts/extract_master.py`. Читаю `prs.slide_master`:
- Все shapes на мастере → их позиции, цвета, шрифты (это дефолты для всех слайдов)
- `prs.slide_master.slide_layouts` → для каждого layout:
  - Имя (`layout.name`)
  - Placeholders (тип, позиция, размер)
  - Overrides цветов и шрифтов относительно мастера

Сохраняю `analysis/master_layouts.json` — это «система» дизайна как задумал дизайнер.

**Чего не делаю:**
Не смотрю на конкретные слайды — только master и layouts.
Не пытаюсь рендерить мастер в PNG.

**Проверка:**
В `master_layouts.json` минимум 5 разных layouts с именами.
Для каждого layout есть список placeholders с типами.

### Шаг 9 — Каталогизировать лейауты: назвать и схематизировать

**Что делаю:**
Вручную разбираю `master_layouts.json` и `geometry_dump.json`. Для каждого уникального паттерна расположения зон:
- Даю имя (TitleSlide, SectionDivider, TwoColumn, FullImageOverlay, StatCard, ListContent и т.д.)
- Рисую ASCII-схему слотов и описываю каждый (что туда идёт, размер в %)
- Отмечаю типичный цвет фона и текста для этого лейаута

Сохраняю `analysis/layout_catalog.md` — это основной артефакт для Storybook.

**Чего не делаю:**
Не создаю React-компоненты на этом шаге — только документирую.
Не выдумываю лейауты которых нет в файлах.

**Проверка:**
Каждый layout из `master_layouts.json` покрыт хотя бы одним паттерном в каталоге.
Для каждого паттерна есть пример — номер слайда откуда взят.

### Шаг 10 — Синтез: назначить роли цветам и собрать палитру

**Что делаю:**
Читаю `color_frequency.json`, `theme_colors.json`, `layout_catalog.md`.
Назначаю каждому топовому цвету роль:

| Роль | Описание |
|------|----------|
| `brand-primary` | Основной акцент (кнопки, иконки, подчёркивания) |
| `brand-secondary` | Второй акцент (если есть) |
| `bg-dark` | Фон тёмных слайдов |
| `bg-light` | Фон светлых слайдов (часто #ffffff или оттенок) |
| `text-primary` | Основной текст на светлом |
| `text-on-dark` | Текст на тёмном фоне |
| `text-muted` | Подписи, второстепенный текст |
| `border` | Линии, разделители |

Дополняю контекстом: «этот цвет используется только в section dividers», «этот только в таблицах» и т.д.
Сохраняю `analysis/color_roles.json`.

**Чего не делаю:**
Не придумываю роли — только те что подтверждены данными из шагов 4–5.
Не добавляю цвета которых нет в файлах.

**Проверка:**
Каждый цвет с частотой > 2% покрыт ролью.
Нет ролей с одинаковым hex.

### Шаг 11 — Синтез: собрать типографическую шкалу

**Что делаю:**
Читаю `typography_dump.json`. Группирую по размеру + роли placeholder:
- Нахожу размер для TITLE placeholder → это `display` или `h1`
- Нахожу размер для BODY → это `body`
- Нахожу минимальный встречающийся размер → это `caption`
- Восстанавливаю полную иерархию: display / h1 / h2 / h3 / body / small / caption

Для каждого уровня фиксирую:
- `font-family`
- `font-size` (px при 96dpi и pt)
- `font-weight`
- `line-height`
- `letter-spacing` если задан
- `color` (из `color_roles`)

Сохраняю `analysis/typography_scale.json`.

**Чего не делаю:**
Не усредняю — если на разных слайдах H1 = 40pt и 44pt, фиксирую оба и выбираю наиболее частый.
Не выдумываю уровни иерархии — только те что реально используются.

**Проверка:**
Шкала содержит минимум 4 уровня.
Каждый уровень встречается минимум на 3 слайдах из разных файлов.

### Шаг 13 — Обновить компоненты лейаутов: реальные JVO-цвета и пропорции

**Что делаю:**
Создаю `src/tokens.ts` — единый файл с токенами:
```ts
export const colors = { brandPrimary: '#...', bgDark: '#...', ... }
export const type = { h1: { size: 64, weight: 700, family: '...' }, ... }
export const spacing = { slidepadH: 120, slidepadV: 80, ... } // px из геометрии
```
Обновляю все компоненты в `src/layouts/` — заменяю placeholder-значения на токены.
Обновляю stories — добавляю stories с реальными JVO-данными (не только с placeholder-текстом).

**Чего не делаю:**
Не удаляю `args` в stories — Controls panel должен оставаться рабочим.
Не хардкожу цвета внутри компонентов — только через токены.

**Проверка:**
Запускаю Storybook, открываю каждый лейаут — он визуально совпадает с реальным слайдом JVO.
`src/tokens.ts` — единственное место где живут числа.

### Шаг 14 — Добавить новые лейауты найденные в файлах

**Что делаю:**
По `layout_catalog.md` нахожу паттерны которых нет в текущем Storybook.
Для каждого нового лейаута:
- Создаю `src/layouts/НазваниеLayout.tsx` — React-компонент со слотами
- Создаю `src/layouts/НазваниеLayout.stories.tsx` — минимум 2 story (дефолт + с реальными данными JVO)
- Добавляю ASCII-схему слотов в JSDoc компонента

**Чего не делаю:**
Не создаю лейауты «на будущее» — только те что реально встречаются в PPTX.
Не усложняю компоненты — один лейаут = один файл, никаких вложенных абстракций.

**Проверка:**
Число компонентов в `src/layouts/` = число паттернов в `layout_catalog.md`.
Каждый новый компонент имеет story с данными максимально близкими к реальному слайду.

## Что не входит в план
- Рендер слайдов в PNG/PDF для презентации команде
- Экспорт Storybook в статику (build-storybook)
- Git-репозиторий и CI/CD
- Интерактивный редактор слайдов
